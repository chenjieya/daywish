## 1. 产品与技术选择

“好日将至”是一个安静常驻的桌面倒计时小窗，显示发薪、官方节假日和农历春节。无需登录，日期在本机计算和保存；仅在自动或手动检查日历更新时联网，不上传个人设置。

| 平台 | 实现 | 选择原因 |
|:--|:--|:--|
| Windows | Electron、Vue 3、TypeScript、Vite | 优先精致 UI、CSS 定制能力和桌面功能的可维护性 |
| macOS 26+ | SwiftUI、AppKit、Swift Package Manager | 系统原生 Liquid Glass，macOS 27+ 启用玻璃交互反馈 |

双端共享视觉规则、日历数据和测试样例，各自实现原生窗口能力，不共享 UI 代码。Windows 运行时仅 Vue；其余依赖为开发和构建工具。Mac 无第三方依赖。不采用 Electron 统一双端，是用户确认的技术选择。

## 3. 日期规则

### 3.1 发薪

- 默认每月 10 日，可设置 1—31 日或月末。
- 月份不足约定日时取当月最后一天；当天显示 0 天。
- 遇休息日支持按原日期、提前至工作日、顺延至工作日。
- 官方补班日期优先于周末判断，官方假期内日期视为休息日。
- 枚举上月到后两个月后排序，覆盖跨月顺延、下月工资提前到本月等情况。
- 缺少该年官方调休数据时保留约定日期并显示提示，不伪造工作日规则。
- 实际到账仍以公司安排为准。

### 3.2 节假日

- 中国大陆全体公民的官方节日假期，包含调休形成的连休。
- 倒计时指向假期开始日；普通周末不会成为独立的目标。
- 假期进行中显示“正在放假”，结束次日查找下一假期。
- 放假安排目前覆盖 2026、2027 年。没有后续官方数据时显示待更新。

### 3.3 春节与时区

- 春节单独指农历正月初一，与春节假期首日分开计算。
- 使用中国科学院紫金山天文台《2026年日历资料》和大陆政务公开资料。内置正月初一覆盖 2025—2029 年，其中 2025 年用于前一周期进度计算；不继续使用香港历表。
- 新年度春节通过国务院年度通知中的“农历除夕”或“正月初几”等锚点计算，不能识别时保留已知数据。
- 实测当前 Node 的 ICU 把 2027 年正月初一算成 2 月 7 日，而大陆官方公告对应 2 月 6 日，因此不依赖系统农历库计算该倒计时。
- 默认用系统时钟换算北京时间 `Asia/Shanghai`，提供跟随系统时区选项；跨天定时器也按所选时区调度。
- 日差按公历日期计算，避免夏令时导致 23/25 小时日差。

## 4. 视觉与桌面交互

默认在桌面右下角展示 340 × 236 的小窗，紧凑间距为 340 × 204。三个倒计时平行排列，用细进度条表达等待过程。设置临时展开为 340 × 490。Windows 改由系统绘制背景材质、圆角和阴影，客户区不再保留透明间距，与组件尺寸一致。

渲染层与 Electron 共享 `src/types/window.ts` 的尺寸和视图契约；主窗、紧凑、面板三种状态通过 `set-view-mode` 同步，保存设置不再改变窗口大小。面板打开时倒计时区域使用 `display: none`，避免透明面板透出底层文字。返回主窗后恢复打开面板前的位置。

| Token | 白色磨砂 | 用途 |
|:--|:--|:--|
| 深石墨 | `#233743` | Windows 主文字 |
| 灰蓝 | `#6C8B9E` | Windows 进度条 |
| 雾白 | `#F7FAFC` | Windows 磨砂底色 |
| 深蓝灰 | `#30434F` | Windows 日期与辅助信息 |
| 字体 | Windows 系统中文字体、Mac 系统字体；数字等宽显示 | 小窗可读性与稳定排版 |

Windows 新增独立的 `frostOpacity`，默认 84%，范围 70%—96%；旧设置缺少此字段时自动采用默认值，不继承旧版全透明的 `opacity: 0`。使用浅色底与不透明的深色前景，浓度只改变底色，文字不变淡。旧工资日、时区及其他偏好保留。Mac 的 `opacity` 与原生实现不变，默认零衬底，原生折射、高光和交互由系统实现。系统材质受透明度与辅助功能设置影响。

工资进度为相邻实际发薪日之间的进度，节假日进度为上个假期结束次日到下个假期首日之间的进度，春节进度为相邻正月初一之间的进度。缺少上一周期时显示未知进度，不填虚构百分比。

窗口可拖动、置顶、收起至托盘或菜单栏、记住位置、切换迷你模式、设置开机启动。开机启动默认关闭。设置面板在迷你模式下临时展开。关闭按钮收起，托盘或菜单栏提供明确的退出操作。

Windows 11 22H2+ 使用系统 Acrylic，固定浅色主题。使用非 layered 的窗口（`transparent: false`）搭配透明客户区底色与系统材质，避免将直接穿透桌面的透明窗口当成磨砂；较旧系统以浅色不透明底兜底。网页使用 24px 背景模糊及相同浅色衬底近似审核，不启用 SVG 折射；原生模式由系统完成桌面背景模糊，CSS 不冒充系统合成器。

`?preview=macos` 单独展示 Mac 玻璃示意，不能替代真机验收。Mac 使用 `NSGlassEffectView`，将 SwiftUI 的 `NSHostingView` 放入该材质的 `contentView`，采用 `.clear`，圆角 20，衬底为 0% 时 `tintColor = nil`；在 macOS 27+ 设置 `effectIsInteractive = true`。不再使用普通 `NSVisualEffectView` 充当 Liquid Glass。

Mac 网页示意用独立材质层和 SVG 位移贴图近似表现折射，不模糊前景文字。Chromium 使用 SVG backdrop filter，其他浏览器保留 CSS 玻璃预览。网页无法完全复制系统合成器，两端原生视觉均需真机验收。没有持续动画或空闲渲染循环。

## 5. 安全、性能与验证

- 日历默认自动更新：每年首次使用检查，9 月起若次年数据尚未收录则每周重试；失败每天最多重试一次，用户可手动立即检查。退出应用期间不安装额外常驻更新服务。
- `holiday-cn` 的公开 JSON 仅作为国务院通知 URL 索引，支持 CDN 和 GitHub 两个入口；日期仍从中国政府网原文解析。该索引是第三方服务，不是政府官方 API。
- 网络数据校验通知年份、全年七类节日、有效日期、假期重叠和补班冲突。校验或网络失败保留本地缓存，不覆盖为半份数据。网页开发服务器代理请求，Electron 使用主进程网络 API，Mac 使用 URLSession。

- Electron 启用 `contextIsolation` 和 `sandbox`，关闭 Node integration，禁止页面打开任意新窗口和导航。
- preload 仅暴露固定 IPC 操作，设置逐字段校验；不开放文件路径、shell 或任意 IPC 通道。
- 本地设置原子写入并串行处理；窗口位置防止落在已拔出的显示器之外。
- 空闲状态不执行持续动画或每秒计时。跨天定时器、唤醒与窗口激活触发校准；Windows 也处理系统时间变更。
- 定时器、通知观察者、IPC 监听均有对应清理。
- Windows 包构建不等于原生窗口验收；Mac 源码完成不等于已通过 Xcode 编译，具体状态见交付说明。
- 真实内存、CPU、耗电和模糊效果需要分别在 Windows、Mac 真机测量，不用安装包体积推算。
