## 1. 版本与范围

Windows 当前源码改为浅色磨砂：Windows 11 22H2+ 使用原生 Acrylic 与浅色衬底，较旧系统使用浅色不透明底兜底。磨砂浓度默认 84%，可调 70%—96%，文字始终不透明。Mac 为 SwiftUI + AppKit 原生应用，最低 macOS 26，采用系统 `NSGlassEffectView`；macOS 27+ 启用材质交互反馈。默认网页展示 Windows 磨砂模式，`?preview=macos` 展示 Mac 玻璃示意，均不能替代真机验收。

核心功能包括工资、官方假期、正月初一倒计时；工资日及休息日规则设置；紧凑白色磨砂与进度条；玻璃不透明度；北京时间／系统时区；日历自动更新；拖动、置顶、位置保存；托盘或菜单栏；紧凑间距；开机启动。

用户已明确要求打包磨砂版，当前 Windows 安装包为 v0.2.2，已完成类型检查、正式构建与 NSIS 打包。后续界面迭代继续先网页审核，得到打包指令后再生成安装包。`release/` 中旧安装包与 Mac 源码 ZIP 仍为早期产物。

用户安装 v0.2.0 后反馈主窗被拉高、设置透出倒计时文字和灰色背景。v0.2.1 已包含统一视图尺寸、固定组件高度、面板打开时隐藏倒计时和移除 Windows Acrylic 的修复。包内版本与 9 个构建文件已核对；原生窗口效果仍未完成真机验收。`release/` 中 v0.2.0 仍包含上述问题，不应当作修复版安装。

用户安装 v0.2.1 后反馈透明材质导致背景文字干扰，已要求 Windows 改用磨砂。v0.2.2 已包含磨砂及独立的 `frostOpacity`，旧版 `opacity: 0` 不会继续导致透明；保留其他偏好。原生客户区改为 340 × 236／204／490，由系统绘制阴影，不保留旧透明边距。包内版本与 10 个构建文件已核对；原生 Acrylic 仍待真机验收。现有 v0.2.1 安装包仍为透明版，不包含磨砂改动。

当前本地可验证 Windows 的 TypeScript、前端构建和共享日期测试。Mac 必须在 macOS 上运行 Swift 测试、构建与真机验收。不能把浏览器预览当成原生玻璃效果的验收结果。

## 2. Windows 开发与打包

在项目根目录 `C:\Users\admin\Desktop\code\token\daywish` 执行。需要 Node.js 22.12+ 和仓库声明的 pnpm 10.28.0。

```powershell
pnpm install
pnpm dev
```

`pnpm dev` 启动 Vite 后读取实际端口，再启动 Electron。前端代码热更新，桌面主进程代码修改后重启该命令。

```powershell
pnpm ts:check
pnpm test
pnpm build
pnpm start
```

浏览器单独预览：

```powershell
pnpm dev:web
```

使用终端输出的真实地址。浏览器可体验倒计时、主题、透明度和设置；原生窗口拖动、置顶、托盘和开机启动需要桌面版。

构建安装程序：

```powershell
pnpm package:win
```

产物目录为 `release/`；本轮安装程序名为 `Daywish-0.2.2-Windows-x64-Setup.exe`，123,172,842 字节，约 117 MB。先通过托盘菜单退出旧版，再运行安装包覆盖安装。安装包包含 Electron 运行环境，用户不需要 Node.js。当前是未签名开发版本。

安装包 SHA-256：`7986f628247c9c6b94d998c20317cddde30e63aa18f5ca2042e85e9608376760`。

首次从旧版升级时，白色衬底重置为 0%，工资日、时区、置顶等其他偏好保留；保存后的 `appearanceVersion` 为 2，此后会保留用户自行调整的衬底浓度。

本机缓存放在 `.cache/`，Electron 二进制在安装依赖时准备；构建使用本地二进制。遇到网络限制时检查现有代理设置，不要关闭证书校验。

## 3. Mac 免费安装与构建

### 3.1 是否必须上架或付费

可以不通过 Mac App Store 分发 `.app` 或 ZIP，也可以使用免费本地临时签名构建。普通个人 Mac 可按 Apple 官方流程在首次打开时确认放行。受组织管理的 Mac 可能限制此操作。

首次运行时：

1. 解压 ZIP，把“好日将至.app”拖入“应用程序”。
2. 尝试打开应用。
3. 若系统拦截，进入“系统设置 → 隐私与安全性”，找到该应用，点击“仍要打开”并确认。

这不等同于正式的 Developer ID 签名或 Apple 公证。若后续希望向公众分发并减少首次安装提示，可再考虑付费开发者账号及签名、公证。当前没有这项费用依赖。

### 3.2 在 Mac 本地构建

把整个项目复制到 Mac，保留 `shared/` 和 `macos/` 的相对位置。需要 Xcode 27 或更新版本，包含 macOS 27 SDK；构建脚本会先检查 SDK，以编译最新的原生玻璃交互接口。无需安装 Node、pnpm 或第三方 Swift 包。

```bash
cd /你的项目目录/daywish
bash macos/build.command
```

脚本会同步共享日历、执行 Swift 测试、构建当前 Mac 架构应用、装配资源包、免费临时签名并生成 ZIP。

输出位置：

```text
macos/build/好日将至.app
macos/build/Daywish-0.2.2-macOS-arm64.zip
```

Intel Mac 上 ZIP 后缀为 `x86_64`。此脚本生成运行构建机器架构的版本，不宣称已经生成通用二进制。

也可用 Xcode 打开 `macos/Package.swift` 阅读和调试。直接 `swift run` 不等于已装配的 `.app`，开机启动建议在应用程序目录中的 `.app` 上设置。

### 3.3 自动构建入口

验证入口为 [验证与构建 Mac 原生版](https://github.com/chenjieya/daywish/actions/workflows/macos.yml)，对应 `.github/workflows/macos.yml`。Mac 源码或共享数据推送至 main 时自动执行，也可手动运行。使用 GitHub 官方 `xcode-27` Apple Silicon runner；当前该镜像处于预览阶段。普通 `macos-latest` 的 Xcode 26 不满足本项目编译 SDK 27 的要求。

验证工作流执行 Swift 测试、Release 构建、资源装配和临时签名校验，然后启动装配后的 `.app`，确认共享资源、原生窗口初始化完成，再关闭本次检查进程。该步骤仅在设置 `DAYWISH_SMOKE_TEST=1` 时执行，本地构建默认不启动应用。ZIP 在 Actions 的 `Daywish-macOS` 构建附件中；验证工作流本身不更新官网下载。

首次验证 [Run 45130709107](https://github.com/chenjieya/daywish/actions/runs/45130709107) 已全部通过，源码提交 `49a2ce3`。正式交付使用 [发布客户端并更新官网下载](https://github.com/chenjieya/daywish/actions/workflows/release.yml)，选择 `macos`，或推送匹配根版本号的 `macos-v0.2.2` 标签。发布流程再次测试与构建，上传 GitHub Release 后通过已配置的 production Secrets 自动更新官网，保留 Windows 下载记录。

正式发布 [Run 45131145697](https://github.com/chenjieya/daywish/actions/runs/45131145697) 已成功，官网同步与公网下载校验通过。可从 [官网](https://daywish.alvis.org.cn/) 或 [Mac v0.2.2 Release](https://github.com/chenjieya/daywish/releases/tag/macos-v0.2.2) 下载。ZIP 为 `Daywish-0.2.2-macOS-arm64.zip`，487,943 字节，SHA-256 为 `551f766b8952e6506a11fbc673dcf2fcb615d0d9fd983106810f1ef7f7f1ba0d`。当前正式产物只支持 Apple Silicon，运行最低 macOS 26，采用免费临时签名，无 Developer ID 签名或公证；首次安装按 3.1 节放行。

## 4. 数据、设置与升级

| 内容 | 路径或规则 |
|:--|:--|
| 官方放假表 | `shared/calendar.json`，当前覆盖 2026、2027 年 |
| 春节历表 | `shared/springs.json`，大陆来源，当前覆盖 2025—2029 年 |
| 共享边界样例 | `shared/date-cases.json` |
| Windows 设置 | 系统应用数据目录下“好日将至”的 `settings.json`，实际目录由 Electron 的 `userData` 决定 |
| Windows 测试隔离目录 | 设置 `DAYWISH_USER_DATA` 为项目内路径，仅用于开发测试 |
| Mac 设置 | `~/Library/Application Support/Daywish/settings.json` |
| Mac 窗口位置 | 应用对应的 UserDefaults |

应用每年自动检查日历数据，9 月起次年尚未收录时每周重试；网络失败后最多每天重试一次，设置内支持立即检查。只更新日历 JSON，不需要重新安装。关闭应用时不执行检查，下一次打开或唤醒后按到期规则检查。

为定位国务院通知，使用开源 `holiday-cn` 的公告链接索引；实际放假日期、补班日期和正月初一均解析中国政府网原文，不能识别或校验失败时继续使用本地数据。第三方索引故障或政府页面变更可能导致检查失败，设置会显示真实状态。

维护内置数据时可手动运行：

```powershell
node --experimental-strip-types scripts/update-calendar.ts 2027
```

原 `scripts/update-springs.mjs` 入口现在调用大陆公告更新逻辑，已移除香港天文台抓取逻辑。

更新数据后：

```powershell
node scripts/sync-mac-data.mjs
pnpm test
```

Mac 资源目录内 JSON 是自动生成副本，不应单独编辑。Windows 测试会检查副本与共享源逐字节一致，Mac 构建脚本也会再次同步。

日历数据自动更新，应用程序本身仍通过新版本安装包升级。设置结构变化前需增加兼容读取，不直接删除用户设置。默认北京时间，可选择跟随系统；系统时钟不准确时，应用不会自行联网校时。
