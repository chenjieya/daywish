## 1. 使用与升级

现有 v0.2.2 没有软件更新器，需要最后手动安装一次 v0.3.0。后续打开设置中的“软件更新”，检查、下载并确认重启即可完成升级，不需要用户寻找安装包或重新选择安装位置。工资日、外观和窗口位置保留。

软件版本检查与每年的日历数据更新使用独立开关。默认每天自动检查软件，不自动下载或强制重启。Windows 运行期间按 24 小时限频，启动后延迟 15 秒检查，唤醒后检查是否到期；Mac 由 Sparkle 调度。

Windows 显示检查状态、更新说明、下载进度和“重启并更新”。下载失败可重新检查，原软件继续使用；安装前等待设置持久化，保存失败时取消安装。Mac 设置与菜单栏均提供入口，下载、签名验证、替换和重启使用 Sparkle 标准原生窗口。Mac 最低 macOS 26，当前发布架构为 Apple Silicon。

## 2. 更新器与发布源

| 平台 | 更新器 | 更新源 | 校验与安装 |
|:--|:--|:--|:--|
| Windows | electron-updater 6.8.11、现有 NSIS | `https://daywish.alvis.org.cn/updates/windows/latest.yml` | 完整安装包 SHA-512；用户确认后由更新框架启动静默升级并重新打开应用 |
| Mac | Sparkle 2.10.1，SwiftPM 固定版本 | `https://daywish.alvis.org.cn/updates/macos/appcast.xml` | 解压前 Ed25519 验签，标准原生更新与重启 |

Windows 当前安装包没有 Authenticode 签名，配置明确不要求发布者证书，更新依赖固定 HTTPS 官网及包哈希；没有宣称已经完成 Windows 正式代码签名。Mac 使用免费临时应用签名与独立 Ed25519 更新包签名，后者不等同于 Developer ID 或 Apple 公证。

发布记录新增 `sha512`；Mac 另有公开的 `edSignature`、`publicKey`。服务端从已经发布的记录生成更新源，按数字比较版本；旧 v0.2.2 缺少更新校验字段，不作为应用内更新条目。两个平台相互独立，补同步旧版本不会把新版更新源降级。官网静态文件更新不覆盖版本记录或更新源。

安装包仍作为 GitHub Release 附件发布。默认更新源指向实际 GitHub 下载地址，已有服务器镜像时保留对应镜像。Windows 本地 electron-builder 生成的 `latest.yml` 不直接上传服务器，服务端使用实际正式 Release 记录生成带完整下载地址的清单。

## 3. Mac 更新签名

复用已经配置的 production 部署 Secrets。GitHub Mac 工作流通过严格主机公钥校验的 SSH 获取公开验签密钥；首次由部署服务器 OpenSSL 生成 Ed25519 私钥。私钥保存在 `/srv/daywish/keys/sparkle-ed25519.pem`，目录 700、文件 600，不传回 GitHub、不写入应用或仓库。应由服务器维护者安全备份该私钥。

Mac ZIP 构建后传至本项目服务器暂存目录，先核对 CI 提供的 SHA-256 再签名。CI 再次使用公钥验证实际 ZIP 签名，校验通过才生成发布记录。服务端已存在签名发布记录时，私钥丢失或与已发布公钥不一致会停止发布，禁止静默生成新密钥使旧客户端失去更新能力。

OpenSSL 需支持 Ed25519 和 `pkeyutl -rawin`。本轮本地 OpenSSL 签名、验签、篡改拒绝及密钥丢失保护测试均通过。生产服务器公钥准备已在 Mac 验证工作流中执行成功。

Mac 本地构建现在需要 Sparkle 下载及公开公钥：在可信渠道取得服务器已发布公钥，设置 `DAYWISH_UPDATE_PUBLIC_KEY` 后执行 `bash macos/build.command`。不能为已有客户端擅自替换公钥。云端工作流自动准备公钥，无须用户重新配置 GitHub Secrets。

## 4. 发布流程

1. 修改根 `package.json.version`，并提交对应 `.github/release-notes/<平台>-<版本>.txt`。
2. Mac 源码变更先等待“验证与构建 Mac 原生版”通过。
3. 手动运行“发布客户端并更新官网下载”，选择平台；也可推送匹配版本的 `windows-vX.Y.Z` 或 `macos-vX.Y.Z` 标签。
4. CI 执行测试和平台构建，Mac 另行签名并复核签名。
5. 上传全部附件后发布正式 Release，串行同步官网记录和软件更新源。
6. GitHub runner 检查公网首页、静态资源哈希、下载 HEAD、Windows 更新清单及 Mac 更新签名字段。

同平台同版本不覆盖已发布内容；重新构建后发生包差异时需增加版本号。仅重跑失败的 publish job 会复用该轮已经生成的产物。

本轮原工作区 `.git` 只有读取权限，发布使用项目内独立检出 `.cache/release-publish/`。原目录源码保留，GitHub 提交来自该独立检出；未修改原目录 Git 元数据或权限。后续本地 Git 操作需留意原目录分支尚未随发布提交前进。
